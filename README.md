# Tiny Defense

敵が決まったルートを通ってゴールを目指すので、タワーを置いて防ぐ2Dタワーディフェンスゲームです。
Unity と C# の学習の成果として、ゲームの流れを一通り作りました（タイトル → Wave進行 → 勝敗 → リトライ）。

## プレイ
**unityroom でブラウザからすぐに遊べます（インストール不要）**

👉 【[https://unityroom.com/games/test999999999999](https://unityroom.com/games/tinydefense)】

- 制作期間: 【2週間】
- 制作人数: 1人

## 遊び方
| 操作 | 内容 |
| --- | --- |
| Startボタン | ゲーム開始 |
| タワー選択ボタン | 設置するタワー（通常 / 魔法）を切り替え |
| 左クリック（空いた場所） | 選択中のタワーを設置 |
| 左クリック（設置済みタワー） | 強化パネルを開く |
| Retryボタン | ゲーム終了後に最初からやり直し |

### ルール
- 初期ライフは **15**、初期所持金は **150**
- 敵がゴールに着くとライフが減り、0になるとゲームオーバー
- 敵を倒すと所持金が増え、その所持金でタワーを設置・強化する
- 全 **5 Wave** を耐えきるとゲームクリア

## 設計で工夫した点

### 1. MVC構成で「ロジック」と「見た目」を分けた
Model（`GameModel`、`EnemyModel`、`TowerModel` など）は Unity に依存しない普通の C# クラスにしました。HPの計算や強化処理などのルールだけを持たせています。
移動・攻撃・入力は Controller、表示は View / UI が担当します。どこに何が書いてあるかが分かりやすく、ロジックだけを取り出してテストすることもできます。

### 2. ScriptableObjectでパラメータをデータ化した
敵とタワーのステータスは `EnemyData` / `TowerData` というアセットに分けています。
コードを直さずに Inspector 上でバランス調整でき、敵の種類を増やすときもアセットを追加するだけで済みます。
敵の Prefab は1つだけで、`EnemyData` を渡すことでステータスと見た目を切り替えています。

### 3. イベントでゲーム終了を通知した
`GameController` が `OnGameOver` イベントを出し、`WaveController` と `EnemySpawner` がそれを受け取って自分で止まる仕組みです。
GameController が他のクラスを直接止めに行かないので、クラス同士が依存しすぎません。

### 4. タワーの狙う敵の選び方
射程内の敵のうち、**一番ゴールに近い敵**（進んだウェイポイントの数が一番多い敵）を優先して狙います。
進み具合が同じ敵が複数いるときは、タワーから一番近い敵を選びます。これで「ゴール直前の敵を見逃す」ことを防いでいます。

### 5. 不具合が起きやすい箇所への対策
- **多重ヒット**: 同じフレームで複数の弾が当たっても、撃破処理（報酬の加算など）が一度だけ実行されるようにフラグで防止
- **出現順のかたより**: Waveの敵をシャッフルして、同じ種類の敵ばかり続けて出ないように調整
- **設置の制限**: UIの上のクリックは無視し、設置エリアの外や敵の通路の上にはタワーを置けないように判定
- **ゲーム終了後の処理**: 終了後はタワーの攻撃・設置・所持金の変動をすべて止める

## ディレクトリ構成
```

├── Models        # ゲームのルールとデータ（Unityに依存しないC#クラス / ScriptableObject）
│   ├── Game
│   ├── Enemy
│   ├── Tower
│   ├── Wave
│   └── Projectile
├── Views         # 見た目の制御
│   ├── Enemy
│   ├── Tower
│   ├── Projectile
│   ├── Game
│   └── UI
└── Controllers   # 移動・攻撃・入力・進行の管理
    ├── Game
    ├── Enemy
    ├── Tower
    ├── Wave
    └── Projectile
```
